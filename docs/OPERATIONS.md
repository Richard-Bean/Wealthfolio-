# 运行与故障处理

## 运行手册

### 一、持仓截图转 Wealthfolio CSV

#### 1. 准备输入

把一张或多张支付宝基金持仓截图放入：

```text
FinanceBot/data/raw/alipay/
```

正式输入需要包含：

- 基金名称或可识别名称；
- 持有金额；
- 持有收益；
- 持有收益率。

截图模板参考：

```text
FinanceBot/docs/templates/持仓截图模板_打码.jpg
```

打码模板只用于说明布局，不能作为正式输入。

#### 2. 运行

双击项目根目录：

```text
运行截图转CSV.bat
```

也可以把图片拖到 BAT 上。

默认流程：

```text
多张 JPG
→ Windows OCR
→ 模板识别
→ 解析持仓/交易
→ 多图比较和去重
→ 本地净值缓存
→ 份额和成本校验
→ Wealthfolio CSV
```

#### 3. 检查产物

主要产物：

- 结构化持仓输入 JSON；
- OCR JSON；
- 持仓快照对比报告；
- 待确认交易 CSV；
- 已确认后续交易 CSV；
- Wealthfolio 导入 CSV。

#### 4. 人工复核

导入前检查：

1. 对比报告中的重复移除；
2. 同代码金额冲突；
3. 跳过的非基金资产；
4. 待确认基金映射；
5. `manual_review` 和严重校验错误；
6. 警告是否属于收益率口径差异；
7. 账户名是否为“蚂蚁财富”；
8. 日期、份额、平均成本和修正后的收益是否合理。

严重校验错误会阻止导出。只有确认或修复后才能继续。

#### 5. 导入

只导入最终 CSV。导入完成后核对 Wealthfolio 中的活动数量，避免把多个快照重复导入为多次买入。

#### 6. 归档

把已经处理的截图移动到归档目录，避免下次运行重复扫描。

### 二、支付宝交割单 PDF

#### 1. 准备

将一份交割单 PDF 放入：

```text
FinanceBot/data/raw/alipay/
```

PDF 可能包含姓名和身份证信息，不要上传到不受信任的服务。

#### 2. 安装依赖

在 `FinanceBot/` 下运行：

```powershell
pip install -r connectors/alipay/requirements.txt
```

#### 3. 运行

```powershell
python connectors/alipay/scripts/run.py
```

流程：

```text
解析 PDF
→ 获取净值（可关闭）
→ 计算持仓
→ 导出 CSV
→ 对账校验
```

主要产物位于：

```text
FinanceBot/data/processed/alipay/
```

### 三、净值缓存

默认离线运行：

```powershell
python FinanceBot/scripts/update_nav_cache.py --offline
```

显式联网更新时去掉 `--offline`。使用公开净值时必须记录净值日期。

### 四、测试

```powershell
python -m pytest FinanceBot/tests/ -v
```

修改解析、数据模型、去重、校验或导出逻辑时，必须运行相关测试并增加回归用例。

### 五、失败恢复

- 导出 CSV 被 Excel 占用时，关闭文件后重跑。
- 失败运行不得覆盖上一次成功 CSV。
- 后续统一实现临时文件写入和原子替换。
- 失败后保留 OCR、解析 JSON、错误报告和人工复核项。
- 不要手工删除冲突记录；先确认来源和业务语义。

## 故障排查与历史案例

本文件记录已经出现过的问题、诊断方法和处理边界。当前风险和完成状态见 `STATUS.md`。

### 1. 非基金资产被跳过

#### 现象

积存金、黄金理财等记录未进入基金 CSV。

#### 原因

当前截图解析器面向基金持仓模板。非模板资产缺少可靠代码、净值、币种和份额计算规则。

#### 处理

- 在对比报告中查看 `skipped_unsupported_rows`；
- 不要把这些资产强行映射为基金；
- 后续补充资产类型、代码映射、价格来源和份额计算规则后再导入。

### 2. 两个快照被 Wealthfolio 当作两笔买入

#### 现象

不同日期的持仓截图分别导入后，持仓被重复计算。

#### 原因

旧流程把每次完整持仓都写成买入，而不是与上次已接受快照比较。

#### 正确策略

```text
份额不变 → 不生成交易
份额和成本增加 → 生成差额买入
份额减少或消失 → 对账单或人工确认卖出
旧快照乱序出现 → STALE_SNAPSHOT，不生成交易
```

#### 当前处理

正式快照交易推断仍属于 P0。导入前必须人工核对活动数量。

### 3. 缺少稳定来源交易 ID

#### 现象

只能用名称、日期、金额、份额组合去重。

#### 风险

净值变化、四舍五入或重复截图可能让临时指纹失效。

#### 处理

- 来源存在订单号或交易 ID 时必须保存；
- 没有来源 ID 时明确标记临时去重；
- 不把临时指纹描述为完全可靠去重；
- 后续建立 `sourceRecordId` / `sourceTransactionId`。

### 4. 不同基金被映射成同一代码

#### 现象

宝盈、摩根、万家等不同公司的基金被映射到同一国泰基金代码。

#### 原因

旧实现使用低阈值模糊名称匹配，未约束基金公司、份额类别和币种。

#### 已采取措施

- 使用独立 `基金名称代码映射.csv`；
- 本地阈值提高到 `0.88`；
- 强制校验基金公司、A/C 份额类别和人民币/美元币种；
- API 候选歧义进入 `pending_mapping_rows`；
- 同代码金额冲突全部保留并报告。

#### 处理

人工确认前不要强行选择候选。

### 5. OCR 收益金额漏识别首位

#### 现象

例如 `+11.80` 被识别为 `1.80`，导致成本和收益率错误。

#### 已采取措施

- 同一行读取“持有收益”和“累计收益”；
- 使用截图收益率判断可信值；
- 可信备选值能修复漏位时自动修复；
- 保存 `ocr_profit`、`cumulative_profit_ocr`、`ocr_rate` 和修复来源；
- 无可信修复值时标记 `manual_review` 并阻止导出。

#### 处理

先核对截图原始值，再确认修复结果。不要只检查最终 CSV。

### 6. 个人账户 API 不可用

#### 现象

无法获得合法、稳定、长期读取个人余额、持仓和完整历史流水的通用 API。

#### 处理

- 使用用户主动下载的官方文件；
- 浏览器自动化只做用户监督下的下载；
- 公开行情 API 只用于估值；
- 不抓取私有接口，不绕过登录或风控。

### 7. 跨日期相同截图生成重复 CSV 项

#### 现象

同一批次包含不同截图日期，但同一基金的名称、代码和金额一致，最终 CSV 出现重复项。

#### 原因

旧规则要求截图日期相同才判重，但导出时又统一使用批次日期。

#### 已采取措施

同批次同一账户中，名称、代码和金额一致的记录跨日期只保留一项；同代码金额不一致时全部保留并报告冲突。

#### 验证

- 检查对比报告中的 `duplicates_removed`；
- 检查最终 CSV 完全重复项是否为 0；
- 检查相似但不同代码的记录是否仍分别保留。

### 8. CSV 无法覆盖

#### 现象

重新运行后导出文件未更新。

#### 原因

文件通常正被 Excel 或其他程序占用。

#### 处理

关闭文件后重新运行 `运行截图转CSV.bat`，再核对文件行数和对比报告。

### 9. 基金代码映射缺失

#### 现象

报告出现 `pending_mapping_rows`。

#### 处理

1. 核对 OCR 名称是否截断；
2. 核对基金公司、份额类别和币种；
3. 查看 API 候选；
4. 只有唯一、兼容、可信候选才可确认；
5. 确认后写入本地映射表；
6. 重新运行并核对结果。

### 10. 校验错误阻止导出

常见原因：

- 持有金额、收益和成本关系不一致；
- 份额 × 净值与金额差异过大；
- 持有收益与累计收益冲突；
- 截图收益率与计算收益率冲突；
- 适用净值尚未发布；
- 基金代码或币种不一致。

#### 处理

严重错误必须人工确认或修复后导出。仅收益率口径差异、但收益金额一致时，可以接受警告后继续。

### 排查顺序

```text
1. 查看原始截图/账单
2. 查看 OCR 或解析 JSON
3. 查看模板识别和置信度
4. 查看原始值与修复来源
5. 查看映射来源
6. 查看校验错误/警告
7. 查看对比报告
8. 最后检查最终 CSV
```

不要只检查最终 CSV，因为错误可能发生在解析、映射、校验或去重任一阶段。
