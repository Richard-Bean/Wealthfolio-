# Connector 规范

Connector 是“数据进入系统的适配器”，不要求金融机构提供官方 API。

## 架构约束

支付宝、银行和券商个人账户 API 不作为本项目的核心采集方式。普通个人项目无法获得合法、稳定、长期读取个人余额、持仓和完整历史流水的通用 API。

因此默认入口是用户主动下载的官方 CSV、Excel、PDF、对账单和交割单。

## 数据获取等级

| 等级 | 获取方式 | 定位 |
|---|---|---|
| A | 用户下载的 CSV、Excel、PDF、对账单 | 强制默认主路径 |
| B | 用户监督下的浏览器辅助下载 | 可选；不保存登录密码，不绕过验证码 |
| C | 截图 OCR、短信、邮件回单 | 补充路径，不承担完整历史数据 |

公开基金净值、行情 API 可以用于估值，但不能读取或替代用户账户数据。

## 基础接口

```python
class DataSourceConnector:
    source_id: str
    capabilities: set[AcquisitionMode]

    def discover(self, raw_files):
        """识别来源、账户、文件类型和数据批次。"""

    def parse(self, raw_record):
        """把 CSV、Excel、PDF、截图等原始记录解析为来源记录。"""

    def normalize(self, source_record):
        """输出统一数据模型。"""

    def validate(self, normalized_records):
        """执行来源内校验，返回错误、警告和人工复核项。"""
```

## 每个 Connector 必须提供

1. 支持的文件类型和页面/模板版本。
2. 字段映射规则和单位。
3. 原始定位信息。
4. 解析置信度。
5. 低置信度和缺失字段处理。
6. 稳定来源 ID 或明确的临时指纹策略。
7. 去重规则及适用边界。
8. 与统一数据模型的映射。
9. 校验规则和错误等级。
10. 测试样本或脱敏 fixture。

## 支付宝 Connector

### 第一阶段输入

- 邮箱下载的基金交割单 PDF；
- 用户主动提供的持仓截图；
- 用户主动提供的交易状态截图。

### 输出

- 交易来源记录；
- 持仓快照来源记录；
- 待确认交易；
- 已确认后续交易；
- 基金代码映射候选；
- 校验警告和人工复核项；
- Wealthfolio 导入表由统一 Exporter 生成。

### 当前截图模板

- `全部持有`：名称/金额、日收益、持有收益、累计收益；
- `我的持有`：名称、金额/昨日收益、持有收益/率。

模板识别需要记录模板名称、置信度和判断依据。状态栏、导航、营销卡片、筛选标签、底部导航和标签角标不能作为持仓内容。

## 基金映射规则

1. 优先使用本地 `基金名称代码映射.csv`。
2. 本地匹配阈值为 `0.88`。
3. 必须兼容基金公司、A/C 份额类别和人民币/美元币种。
4. 本地未命中时才调用公开基金搜索 API。
5. API 候选歧义、相似度过低或网络失败时保留原始名称并进入 `pending_mapping_rows`。
6. 自动确认结果写回本地映射，后续离线复用。
7. 不同代码不能仅因名称相似而合并。

## 去重规则

- 优先使用 `sourceRecordId` 或 `sourceTransactionId`。
- 缺少来源 ID 时，临时规则必须明确标记局限性。
- 同批次同账户中，名称、代码和金额一致的持仓记录跨日期视为重复候选。
- 同一代码金额不一致时全部保留并报告冲突。
- 相似名称但代码不同必须保留。
- 待确认订单按交易时间、基金、金额和状态跨截图合并。
- 已确认和待确认交易不能混为同一状态。

## 失败行为

- 解析失败不能覆盖已有成功产物。
- 网络失败时应支持本地缓存降级。
- 严重校验错误阻止导出。
- 低置信度、映射歧义和不可靠推断进入人工复核。
